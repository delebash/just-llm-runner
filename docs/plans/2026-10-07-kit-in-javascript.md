# The kit in JavaScript — step 2's build sheet

**What this is:** the working sheet for step 2 of the family's move to Electron and a Node
server — the plan is JustVoice's
[`docs/plans/2026-10-07-electron-node-plan.md`](../../../JustVioce/docs/plans/2026-10-07-electron-node-plan.md)
§4 (read it first), the decisions are in JustVoice's `docs/dev/TASKS.md` ("The family moves to
Electron and a Node server"; step 2's go: "your rec go do it all the full conversion",
2026-10-07). This sheet holds what the plan leaves to the build: where the code lives, the
conventions every port follows, the order, and how each piece is checked. Facts go to the
kit's `docs/dev/RESEARCH.md` §2, not here.

**What it makes:** `server/` — the npm package `@delebash/llm-runner`, the JavaScript twin of
`llm_runner/`. Each app's Fastify server mounts it with `installLlm(app, {…})` exactly as its
FastAPI server calls `install_llm(app, …)` today: the same routes, the same camelCase JSON, the
same tables. Python stays runnable until each app's own step is approved done (plan §2.5), so
for steps 2–5 the kit exists in both languages and **a kit server change lands in both, in the
same change** (plan §10 Q6).

---

## 1 · Layout

```
server/
  package.json          @delebash/llm-runner — ESM, Node ≥ 24 (Electron's)
  vitest.config.js
  scripts/
    node24.mjs          runs a script on Electron's own Node 24 (npm test uses it)
    capture-schema.py   writes a Python base's DDL + column map as JS (db_schema.js)
  src/
    platform/           the stack-level pieces (errors, sql, models, server, procs, log, http, py, …)
    llm/                the LLM stack — one file per llm_runner/llm/*.py
    runner/             the bundled llama.cpp runner — one file per llm_runner/runner/*.py
    index.js            the public surface (installLlm and what the apps import)
  tests/                one <name>.test.js per tests/test_<name>.py, + helpers.js, fixtures/
```

`npm test` runs vitest on Electron 44.7.0's Node (24.21.0) — the runtime the server ships on —
not the machine's `node`. One file: `node scripts/node24.mjs node_modules/vitest/vitest.mjs run
tests/x.test.js`.

## 3 · The conventions — every port follows these

**Files and names**

1. One JS file per Python module, **same file name** (`model_catalog_api.py` →
   `model_catalog_api.js`), so a change that lands in both languages lands in the same-named
   file. Functions and methods camelCase (`make_pricing_router` → `makePricingRouter`,
   `get_service` → `getService`), classes PascalCase, module constants keep their
   `UPPER_CASE`, private `_name` → `name` not exported (or exported with a leading `_` when a
   test reaches it, as the Python test did).
2. **Wire, table and column names never change.** JSON keys stay what Python sends; SQL uses
   the real column names. The runner's `CamelModel` objects use their camelCase (wire) names
   inside the code too (`hw.cpuCores`) — one name per field.
3. Every file starts `// SPDX-License-Identifier: MIT` and a header saying what it is and which
   Python file it ports. Keep the comments that explain WHY (rules, measurements, decisions,
   traps); a long history narrative becomes its conclusion plus "(history: <python file>)".
4. Plain JavaScript ES modules. No TypeScript, no build step.

**Behaviour**

5. **Same answers.** Same status codes, same JSON (fields, order where it's observable, nulls),
   same problem+json errors, same stored text. When Python does something odd, copy it and say
   so in a comment — the route diff (§5) treats any difference as a failure.
6. **Async where Python blocked.** I/O (HTTP, subprocess, sleeps, big file reads) is `async`;
   store and pure functions stay synchronous. A Python thread is an async task
   (`background(name, fn, log)`); a `threading.Lock` around state that never spans an `await`
   is dropped (nothing else runs in between) — one that spans an `await` is a `Mutex`; an
   `Event` is `AsyncEvent`. A database transaction (`tx`) never spans an `await`
   (better-sqlite3 refuses it).
7. **Python semantics that silently differ** — use `platform/py.js`:
   - `round()` → `pyRound` (half-even); `%` on negatives → `pyMod`; `//` → `floorDiv`;
     `int(s)` / `float(s)` that may raise → `pyInt` / `pyFloatParse`;
   - `str(x)` of None/True/False → `pyStr`; truthiness of `[]`/`{}` → `truthy` (an empty array
     or object is TRUTHY in JS);
   - `sorted()` / `.sort()` → `pySorted(xs, key, reverse)` (Python order, stable; JS's default
     sort is string order); `max/min(key=)` → `pyMax`/`pyMin` (first of equals wins);
   - `str.split()` → `splitWs`; `strip(chars)` → `strip`; `casefold` → `casefold`;
   - regex: Python's `\w`, `\b`, `\d`, `\s` are Unicode on `str` — JS's `\w`/`\b` are ASCII.
     Use `W`/`NOT_W`/`B` from py.js with the `u` flag, or `\p{L}`/`\p{N}`; `re.match` anchors
     at the start only (`^` / sticky), `re.fullmatch` at both ends;
   - an object's integer-like keys iterate first in JS (`{"10":…, "2":…}` → "2" first): use a
     `Map` where such keys occur and order matters;
   - `None` → `null` in data; `dict.get(k, d)` → `obj[k] ?? d` only when the value can't be a
     present-but-null (`k in obj ? obj[k] : d` otherwise).
8. **Stored and hashed text keeps Python's format** — JSON with `pyJson` (json.dumps' default
   `", "` / `": "` separators and `\uXXXX` escapes unless the call site passed others; floats
   named in `floats`), dates as `YYYY-MM-DD HH:MM:SS.ffffff` (sql.js does it for `datetime`
   columns). Never `JSON.stringify` for text that is stored or hashed.
9. **Time**: `time.time()` → `Date.now() / 1000`; `time.monotonic()` → `performance.now() /
   1000`; `time.sleep(s)` → `await sleep(s * 1000)`; timeouts given in seconds where Python
   took seconds.
10. **Processes** only through `platform/procs.js` (and, for long-lived servers, the runner's
    spawn door in `runner/process.js`) — never `child_process` directly, never an inherited fd
    (CREATE_NO_WINDOW needs every stdio piped or ignored; kit register §5).
11. **HTTP** only through `platform/http.js`'s `fetch` (called as `http.fetch`, so a test can
    spy it). Provider SDKs (`openai`, `@anthropic-ai/sdk`, `@google/genai`) replace the Python
    SDKs one for one.
12. **Logging**: `const log = getLogger("llm_runner.<package>.<module>")` — the Python logger's
    name — and the same messages and levels.

**Storage**

13. Stores reach the database through `db.session()` (the shared handle). Python's
    `s.query(X).filter(…).order_by(…)` becomes explicit SQL with the **same ORDER BY** — and no
    ORDER BY where Python had none (SQLite then returns rowid order, as it did for Python).
    `s.get(X, pk)` → `h.get(table, pk)`; adds → `h.insert` (Python-side defaults filled);
    attribute edits + commit → `h.update`; a multi-statement change → one `h.tx(() => …)`.
14. A seed function takes the handle (`seedX(h)`) where Python took a session, and the caller
    runs it inside `h.tx`.
15. A row goes out in its wire shape: the camelCase object the Python `_to_wire` built — every
    field its pydantic model has, defaults included.

**Models and routes**

16. A pydantic model is a TypeBox schema (`platform/models.js` header shows each field form). A
    field with a default is `opt(schema, default)`; a free `dict` is
    `T.Record(T.String(), T.Any())` (never `T.Object({})`); `Literal` → `literal(...)`;
    `extra="forbid"` → `strictObject`. `Foo(**x)` → `model(Foo, x)`. Python's `int` field →
    `T.Integer()`, `float` → `T.Number()` — that difference is also what tells `pyJson` which
    numbers are floats.
17. `make_x_router(...)` → `makeXRouter(...)` returning an `async function (app) {…}` Fastify
    plugin. Paths verbatim (a FastAPI `prefix` is written into each path). Request bodies,
    query strings and path params get `schema: {body, querystring, params}` from TypeBox;
    a `{x:path}` converter is a `*` wildcard. A query bool (pydantic accepts 1/0/yes/no/
    on/off/true/false) is declared `T.String()` and read with `pyBool` (add it to your module if
    you need it first — see rule 22). `status_code=201` → `reply.code(201)`.
    `HTTPException(s, d)` → `throw new HttpError(s, d)`; `ApiError(...)` and the helpers keep
    their arguments. A sync FastAPI handler (`def`) that blocked becomes `async`.
    `StreamingResponse` / SSE → `reply.raw` with the same headers and frames (kit register §3).
18. **Injection points instead of monkeypatch.** A Python test that patches `mod.fn` becomes
    `vi.spyOn(mod, "fn")` — it reaches every call made through the module namespace, from
    other modules AND from inside the module when the module calls itself as `self.fn()`
    (`import * as self from "./this.js"`). So: **inside a module, call a function through
    `self.` exactly when a Python test patches it.** A patched module VARIABLE becomes a
    property of an exported object (`export const cfg = { X: … }`) that the test assigns and
    restores. Measured: a direct internal call is NOT reached by the spy.

**Tests**

19. `tests/test_<name>.py` → `tests/<name>.test.js`; each `def test_<x>` → `test("<x>", …)`
    with the same name, so the count compares 1:1. Fixtures → helpers or `beforeEach`;
    `tmp_path` → a `mkdtempSync` folder; `monkeypatch.setenv` → `vi.stubEnv` (unstubbed
    automatically); mocks are restored after every test (vitest config).
20. A test that checks a Python-only mechanism (PEP 562 lazy imports, SQLAlchemy sessions,
    threads, pickling) is NOT ported: list it in the test file's header with the reason. A
    test that needs the network, a GPU or a real llama-server keeps Python's gate (env var).
21. A Python test that FAILS today stays failing-equivalent: port it, and if the JS passes or
    fails differently, say which in the header.

**Working in parallel**

22. Only touch the files of your slice. A shared helper you need that isn't in `platform/`
    goes in your own module (exported, marked "candidate for platform/") — the integrator
    moves it. Never edit another slice's file; never commit (the integrator commits).
23. Importing a module another slice ports: use the Python name camelCased from the
    same-named file (`runner/download.py` `stream_download` → `streamDownload` from
    `runner/download.js`). A vitest mock can't stand in for a FILE that doesn't exist yet
    (measured by runner B) — port against the name, and run those tests once the file lands.
24. Call another module's function through its namespace (`import * as hardware`,
    `hardware.usedPoolMb()`), never a destructured import, wherever a test spies it — a
    spy replaces the namespace property, not a binding already copied out.

## 5 · How the step is checked (plan §2)

1. The ported tests pass (`npm test`), counted against the Python files above.
2. **The route diff** — `scripts/route-diff.mjs`: the Python server (docgen's or JustWrite's,
   mounting `llm_runner`) and a small Node host mounting this package, both on a COPY of that
   app's data root (engines and warm-on-boot off), the same GET list sent to both, status +
   JSON compared; the write routes replayed on two fresh copies and both databases compared
   cell by cell.
3. By hand, in the end: a llama-server router starts, loads, stops and is hard-killed, and VRAM
   returns to baseline each time.

## 6 · Found on the way

- better-sqlite3 binds EVERY JavaScript number as REAL (`select typeof(?)` of 5 → 'real'), so
  5 into a TEXT column stored '5.0' where Python stores '5'. `sql.js` now binds whole numbers
  as BigInt (INTEGER) and booleans as 1/0 — what Python's sqlite3 binds. (storage, 2026-10-07)
- pydantic dumps fields in declaration order; `model()` now rebuilds objects in schema order.
- ajv's strict mode refuses a `default` inside a union (`list[Row] | None` whose Row fields have
  defaults) — legal pydantic. createServer runs ajv with `strict: false`, and the preHandler fills
  union defaults (`models.shapeRequest`), as pydantic does.
- On Windows, Node exposes no process handle, so the spawn door attaches the job by pid
  (`OpenProcess`); a grandchild started before the assignment would escape it — as in Python.
- SQLAlchemy runs a table's INSERTs before its DELETEs within one flush; the seed port matches
  it where rowids depended on it (`seedDefaultRunnerBinaries`, `seedDefaultKnobs`,
  `HardwareClassStore.save`).

- The kit's tables have no Python-side callable defaults (the capture listed none); apps' may
  (`registerDefaultFn`).
- TypeBox 1.x hides its markers as non-enumerable properties; a `{...schema}` spread turns
  `~optional` into a real key that ajv's strict mode rejects. `opt()` copies with property
  descriptors.
- `vi.spyOn(namespace, "fn")` reaches calls through the namespace (other modules, and
  `self.fn()` inside the module) but not a direct internal call — measured under vitest 4.1.11.

**Python bugs the ports found (not fixed — to file as FINDINGs in the kit's TASKS; plan §10 Q7
says a fix lands in both languages):**

- `runner/cache_registry.py:120-121` — an `apps` value that isn't a list (e.g. a number)
  raises a TypeError past `except (OSError, ValueError)` into boot; the module promises nothing
  raises into boot. (runner A, 2026-10-07)
- `runner/download.py:231-235` — a resume file holding a non-object (e.g. `[]`) raises an
  uncaught AttributeError and the download crashes. (runner A)
- `runner/models.py:475-481` — `find_inherited_mtp_drafter` loops over a `set` of roots, so
  which drafter is suggested can change between runs (hash order). The JavaScript tries the
  base repo first, then its `-it` root. (runner A)

- `runner/bandwidth.py:131-133`, `:146-149` — the RAM probe's "threaded" copies don't run in

**Where the JavaScript can't match Python exactly (recorded by the ports):** requests'
(connect, read) timeouts became an idle watchdog; a cancelled chunked download aborts requests in
flight; JS can't tell `20.0` from `20` in a parsed JSON number (stored text is unaffected where a
formatter re-writes it); the kit's `\d` regexes are ASCII; `data_api`'s zips aren't
byte-identical to Python's (both sides read each other's); `request.ip` ignores
`X-Forwarded-For`; an SDK's error detail is the JS SDK's own words after the shared
`"{type} {status}:"` prefix (the part JustWrite's regex reads); a cloud SDK's `timeout` covers
only the wait for headers; SDK traffic goes through `http.fetch` (the env proxy) on purpose.
